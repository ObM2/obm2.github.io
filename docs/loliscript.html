LoliScript Reference

LoliScript is the line-based domain-specific language used by OBM2 Pro to define automation scripts. It is both written by hand and generated by the visual Stacker editor.

Overview

LoliScript is a simple imperative language where each line is one instruction. There are no functions, no classes — only block invocations, control flow, and variable assignment. It is case-insensitive for keywords.

ℹ

The Stacker (visual editor) and the LoliScript editor stay fully in sync. Editing one updates the other in real time.

Script Structure

A LoliScript file consists of a sequence of lines. Blank lines are ignored. Each non-blank line is either a:

  • Block invocation — runs a stacker block (REQUEST, PARSE, KEYCHECK, etc.)
  • Control statement — IF, ELSE, END, JUMP, LABEL
  • Built-in command — SET, LOG
  • Comment — line starting with #
# A minimal LoliScript config
REQUEST GET "https://example.com"
PARSE <SOURCE> LR "token:" "\"" -> "token"
KEYCHECK
  KEYCHAIN Success OR
    KEY "<token>" Exists
  KEYCHAIN Failure OR
    KEY "<RESPONSECODE>" EqualTo "401"

Comments

Lines beginning with # are ignored by the interpreter.

# This is a comment
REQUEST GET "https://example.com"  # Inline comments are NOT supported
⚠

Inline comments (after an instruction on the same line) are not supported. Place comments on their own line.

Variables in LoliScript

Variable values are substituted by wrapping the name in angle brackets: <varName>. This substitution happens automatically in string fields before each instruction executes.

SET "greeting" "Hello, <username>! Your score is <score>."
LOG "<greeting>"

See the Variables & BotData page for the full reference including automatic variables and list syntax.

Control Flow

IF / ELSE / END

Conditional branching. The condition is evaluated against a variable using the same operators as Keycheck.

IF "<RESPONSECODE>" EqualTo "200"
  PARSE <SOURCE> JSON "user.token" -> "token"
ELSE
  SET "token" ""
  LOG "Unexpected response code: <RESPONSECODE>"
END

Available Operators in IF

Same as Keycheck: Contains, DoesNotContain, EqualTo, NotEqualTo, Exists, DoesNotExist, GreaterThan, LessThan, MatchesRegex.

JUMP & LABEL

Unconditional jump to a named label. Useful for retry loops or skipping sections.

LABEL retry
REQUEST GET "https://example.com/check"
IF "<RESPONSECODE>" EqualTo "429"
  UTILITY Wait 2000
  JUMP retry
END
PARSE <SOURCE> JSON "status" -> "status"
⚠

Infinite loops via JUMP are possible. Always include an exit condition (IF / Keycheck) before jumping back.

SET & LOG

SET

Assign a value to a variable. The value string supports variable substitution.

SET "apiUrl" "https://api.example.com/v1/user/<userId>"
SET "authHeader" "Bearer <token>"

LOG

Write a message to the run log. Visible in the Debugger's Log tab and in the Runner log panel.

LOG "User: <email> — Status: <RESPONSECODE>"
LOG "Capture: <planType>"

Debugger

The Debugger lets you step through a script line by line with test data, without running the full Runner.

TabDescription
DataLive view of all BotData variables after each step
LogExecution log with timestamps and block names
HTML ViewRendered HTML of the last HTTP or browser response
NotepadScratch pad — test regex patterns, LR anchors, or JSONPath expressions against pasted text

Test Input

Enter test credentials in the Debugger's input field in the same format as your wordlist (e.g. user@example.com:password123). You can also specify a test proxy.
